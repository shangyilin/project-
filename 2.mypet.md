# MyPet (Java Console Game)

## 1. Programming Language(s) Used
- Java (console-based program)
- Java standard library (`Scanner`, `ArrayList`)

## 2. Purpose of the Code
This project is a simple virtual pet game that runs in the console. The player names a pet, then chooses actions from a menu such as feeding or playing. Each action changes the pet’s happiness and hunger levels. The program also shows warnings when the pet is unhappy or too hungry, and it ends the game when the player exits (or when the pet’s status becomes too bad). An action history is recorded and printed at the end.

## 3. Scale of the Project
- 1 main class: `mypet`
- Multiple methods to keep the code organized (`feedPet`, `playWithPet`, `showStatus`, `checkStatus`, `endGame`)
- Uses a loop + menu system to repeatedly accept user input
- Tracks two main stats (happiness, hunger) and logs actions during gameplay

## 4. Use of Object-Oriented Concepts
This program is written with a clear class-based structure. All game logic is grouped inside the `mypet` class, and different parts of the game are separated into methods (for example, feeding, playing, showing status, and ending the game). This makes the code easier to read and change compared with writing everything inside `main()`.  

The program also uses shared variables (such as `happiness`, `hunger`, and `petName`) to represent the pet’s current state, and each method updates that state depending on what the player chooses.

## 5. Use of Data Structures
The main data structure used is an `ArrayList<String>` called `actionHistory`. It stores a record of what the player did (for example, feeding or playing), and the list is printed at the end of the game.  

Besides that, the program uses basic variables (`int` and `boolean`) to store the pet’s status and whether the game should keep running.

## 6. Interesting Use of Data Structures / Algorithms
The core logic of the program is a menu loop combined with simple state updates. Each user choice changes the pet’s stats, and the program checks the stats after every action to decide whether to display warnings or end the game.  

The action history list is also used to show a summary at the end. This makes the program feel more complete because the player can review what they did during the session.
