# Robot Arena (Grid Painting Game)

## 1. Programming Language Used
- Python 3

## 2. Purpose of the Code (Main Functionality)
This project simulates a simple grid-based competition between two robots. The robots move around a square arena and “paint” the cells they leave behind with their own color. After a fixed number of turns, the program counts how many cells each robot has painted and declares the result.

One robot (RedBot) chooses moves randomly, while the other (BlueBot) uses a simple scoring strategy to pick a better move (e.g., prefer empty cells and avoid the opponent’s color).

## 3. Scale of the Project
- Multiple small modules/classes:
  - `Cell`: represents a position (row, col)
  - `Arena`: stores the grid, valid moves, and painting logic
  - `RedBot`: random move strategy
  - `BlueBot`: heuristic move strategy
  - `main`: runs a fixed number of turns and prints the board
- Uses a turn-based loop (e.g., 50 turns) and prints the arena after each turn
- Includes rule checks (e.g., bots cannot move into the same cell)

## 4. Use of Object-Oriented Concepts
The program is organized using several small classes instead of one large script. Each class has a clear role:

- `Cell` stores coordinates and supports equality checks so positions can be compared easily.
- `Arena` manages the grid, checks boundaries, provides valid moves, and updates the map when a bot moves.
- Each bot is an object with its own state (current position, color, icon) and a `pick_move()` method that decides where to go next.

This separation makes the program easier to understand: the arena handles the “world rules,” and each bot only focuses on decision-making.

## 5. Use of Data Structures
The arena grid is stored as a 2D list (a list of lists). Each element represents a cell symbol (blank, a painted color, or a bot icon).

Lists are also used to:
- store the set of valid moves from a position
- build the printed board output

In addition, the code uses simple numeric variables to track scoring in BlueBot and to count painted cells at the end.

## 6. Interesting Use of Data Structures / Algorithms
The key “algorithm” part is the decision logic for BlueBot. Instead of moving randomly, BlueBot scores each possible move and chooses the move with the highest score.

The scoring is based on simple ideas:
- Prefer moving (painting more cells) rather than staying still
- Prefer empty cells to expand territory
- Avoid stepping onto the opponent’s painted cells
- Prefer positions that keep more future movement options (mobility)
